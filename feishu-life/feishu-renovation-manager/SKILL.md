# Feishu Renovation Manager

使用飞书多维表格、文档和云盘管理住宅装修项目的预算、采购、施工、验收、设备入户、结算和统计仪表盘。

## 适用场景

- 建立或维护装修主台账；
- 汇总当前阶段、已完成事项和下一步；
- 更新预算、付款、报价、增减项和结算；
- 跟踪家电、家具和卫浴的送货、安装、试机与验收；
- 核对柜体、墙地面、美缝、门窗、灯具和设备位；
- 创建或优化预算、付款、施工状态、待办和凭证仪表盘；
- 归档合同、报价单、付款凭证、设计图纸和现场照片；
- 将已购买设备同步到个人或家庭资产台账。

## 数据源与配置

飞书应作为装修项目的主数据源。本地文件只用于配置入口或暂存待上传材料，不建立与飞书长期并行的第二套台账。

用户可以提供装修主 Base、总览文档、设计图和合同文件夹，以及可选的资产 Base URL。这些 URL、token、table ID、record ID、dashboard ID、block ID 和本地路径都是运行时配置，不得硬编码到公开 Skill 或示例中。

## 推荐数据表

### 预算与采购

项目、分类、原始金额、已确认增减、待确认增减、当前金额、付款状态、施工/入户状态、批次、优先级、品牌型号、资料来源、备注、下一步。

### 关键口径

项目、金额、计算口径、状态、备注。用于区分已确认金额、预算口径和情景值。

### 设备入户

设备、型号、已知金额、付款状态、批次、入户状态、入户前条件、入户后动作、资料来源、备注。

### 增改与结算

项目、阶段、金额、计算、凭证状态、付款结算、日期、备注。

### 近期重点

事项、当前状态、下一步、完成标准、优先级、状态。

现有 Base 的表名和字段可能不同。每次写入和制作图表前必须实时读取真实结构、单选选项、已有仪表盘和组件，不猜字段或资源 ID。

## 核心原则

1. **主数据唯一。** 先读取飞书现状，旧 Excel、聊天摘要或本地缓存只作为来源证据。
2. **事实、预算和情景值分离。** 暂估金额不能写成已确认付款或最终结算。
3. **状态不可混用。** 已购买、已付款、已送达、已安装、已验收和已结算是不同状态。
4. **新事实优先但保留来源。** 新报价或现场确认不得静默覆盖旧金额，应记录增减和计算口径。
5. **同一项目保留一条主记录。** 过程变化放到增改结算表或备注，避免预算表重复项目。
6. **图表口径透明。** 名称必须明确金额、数量、平均值、筛选范围和数据表来源，不能用数量图冒充金额图。
7. **写后回读。** 修改记录后读取目标记录；修改图表后读取组件计算结果。
8. **删除和对外动作需确认。** 删除文件、记录、表、仪表盘或组件，向商家发送消息，确认报价或付款前必须取得明确授权。
9. **隐私最小化。** 公开模板和普通摘要不包含合同身份信息、地址、手机号、订单号、凭证或 token。

## 标准流程

### 1. 建立实时项目快照

1. 解析主 Base URL；
2. 列出数据表、字段、视图、仪表盘和组件；
3. 读取本次任务涉及的完整记录，确认分页范围；
4. 打开相关合同、报价、设计图或现场材料；
5. 将信息分成已确认、待确认、暂估和冲突四类。

### 2. 更新装修进度

收到现场描述、照片或报价后拆分为已完成、进行中、现场问题和整改、下一步、金额与付款变化、新增凭证、待业主确认。按需更新预算采购、设备入户、增改结算和近期重点，并在总览文档同步高层摘要。

### 3. 预算与结算

- 原始预算保留在原始金额；
- 书面确认的增减写入已确认增减；
- 口述约数、未签报价和可能产生的费用写入待确认增减；
- 当前金额写明计算公式和来源；
- 全局预算变化同步到关键口径表；
- 每笔增改尽量关联报价单、变更单、发票或付款凭证；
- 最终结算前检查重复项、漏项、管理费和已付金额。

### 4. 分阶段验收

验收建议按当前施工阶段生成，避免给出已经过期的准备事项。常见专项包括柜体、墙地面与美缝、卫浴、门窗、灯具和电气、家电设备位。每个整改项至少记录问题、责任方、完成标准、期限和复验结果。

### 5. 设备入户

入户前检查型号、尺寸、搬运通道、安装点位、水电网络和成品保护；入户后检查外观、数量、安装、通电/试水、噪声、渗漏、配件、序列信息和保修资料。设备投入使用后同步资产台账。

### 6. 与资产台账联动

- 装修台账记录预算、付款、送货、安装、验收和结算；
- 资产台账记录真实成交金额、归属、启用、保修、成本和退役；
- 已购买未启用映射为资产`已购买待启用`；
- 实际投入使用后映射为`使用中`；
- 装修暂估金额不得覆盖更可靠的订单实付金额。

### 7. 资料归档

推荐目录为`01_总览与进度`、`02_预算与报价`、`03_设计图纸与图片`、`04_合同与付款`和可选的`05_验收与整改`。上传后回读目录，核对文件名、数量和位置。

### 8. 装修仪表盘与图表

优化前先读取已有仪表盘、组件名称、类型、`data_config` 和计算结果；优先更新已有组件，避免重复创建同口径图表。推荐组合：

- 指标卡：当前预算总额、待办重点数、待补凭证数；
- 分类图：预算分类占比；分类较多时同时或改用按金额展示的横向条形图，避免饼图出现十几个难辨扇区；
- 状态图：施工/入户状态按项目数量统计；
- 付款图：付款状态按当前金额汇总。

图表规则：

- 名称明确写出“金额（元）”“项目数”“待办数”等口径；
- 金额图使用金额字段聚合，状态分布使用记录数量，二者不可混淆；
- 饼图类别过多时优先条形图；保留饼图时标注“全量”，避免误以为只展示主要类别；
- 指标卡可以从不同业务表读取，例如近期重点的待办数量、增改与结算的待凭证数量；
- 同一仪表盘的组件必须串行创建；
- 只有用户要求优化、美化或重排时才调用智能布局；
- 创建、更新和布局后读取组件清单与计算结果，核对总额、待办数、待凭证数和分类维度。

## 输出格式

日常摘要优先包含当前阶段、已完成、P0/P1下一步、金额变化与计算口径、待确认事项和已更新的飞书入口。不在回复中堆砌内部 token、table ID、record ID、dashboard ID、block ID 或底层命令。

## 完成检查

- 实时读取了飞书数据、字段和已有仪表盘；
- 状态、金额和面积等口径没有混淆；
- 已确认、待确认和情景值分离；
- 图表明确区分金额与数量，类别数量适合图表类型；
- 设备状态与资产台账无明显冲突；
- 所有记录和图表写入已回读验证；
- 删除或对外动作已取得授权；
- 输出未泄露个人、合同、账号或内部资源标识。
