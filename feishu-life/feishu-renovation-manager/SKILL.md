# Feishu Renovation Manager

使用飞书多维表格、文档和云盘管理住宅装修项目的预算、采购、施工、验收、设备入户和结算。

## 适用场景

- 建立或维护装修主台账；
- 汇总当前阶段、已完成事项和下一步；
- 更新预算、付款、报价、增减项和结算；
- 跟踪家电、家具和卫浴的送货、安装、试机与验收；
- 核对柜体、墙地面、美缝、门窗、灯具和设备位；
- 归档合同、报价单、付款凭证、设计图纸和现场照片；
- 将已购买设备同步到个人或家庭资产台账。

## 数据源与配置

飞书应作为装修项目的主数据源。本地文件只用于配置入口或暂存待上传材料，不建立与飞书长期并行的第二套台账。

用户可以提供：

- 装修主 Base URL；
- 总览文档 URL；
- 设计图和合同文件夹；
- 可选的资产 Base URL。

这些 URL、token、table ID、record ID 和本地路径都是运行时配置，不得硬编码到公开 Skill 或示例中。

## 推荐数据表

### 预算与采购

项目、分类、原始金额、已确认增减、待确认增减、当前金额、付款状态、施工/入户状态、批次、优先级、品牌型号、资料来源、备注、下一步。

### 关键口径

项目、金额、计算口径、状态、备注。用于区分已确认金额、预算口径和情景值。

### 设备入户

设备、型号、已知金额、付款状态、批次、入户状态、入户前条件、入户后动作、资料来源、备注。

### 增改与结算

项目、阶段、金额、计算、凭证状态、付款结算、日期、备注。

### 近期重点

事项、当前状态、下一步、完成标准、优先级、状态。

现有 Base 的表名和字段可能不同。每次写入前必须实时读取真实结构和单选选项，不猜字段 ID。

## 核心原则

1. **主数据唯一。** 先读取飞书现状，旧 Excel、聊天摘要或本地缓存只作为来源证据。
2. **事实、预算和情景值分离。** 暂估金额不能写成已确认付款或最终结算。
3. **状态不可混用。** 已购买、已付款、已送达、已安装、已验收和已结算是不同状态。
4. **新事实优先但保留来源。** 新报价或现场确认不得静默覆盖旧金额，应记录增减和计算口径。
5. **同一项目保留一条主记录。** 过程变化放到增改结算表或备注，避免预算表重复项目。
6. **写后回读。** 修改金额、状态或下一步后读取目标记录验证。
7. **删除和对外动作需确认。** 删除文件、记录、表，向商家发送消息，确认报价或付款前必须取得明确授权。
8. **隐私最小化。** 公开模板和普通摘要不包含合同身份信息、地址、手机号、订单号、凭证或 token。

## 标准流程

### 1. 建立实时项目快照

1. 解析主 Base URL；
2. 列出数据表、字段和相关视图；
3. 读取本次任务涉及的完整记录，确认分页范围；
4. 打开相关合同、报价、设计图或现场材料；
5. 将信息分成已确认、待确认、暂估和冲突四类。

### 2. 更新装修进度

收到现场描述、照片或报价后拆分为：

- 已完成；
- 进行中；
- 现场问题和整改；
- 下一步；
- 金额与付款变化；
- 新增凭证；
- 待业主确认。

按需更新预算采购、设备入户、增改结算和近期重点，并在总览文档同步高层摘要。

### 3. 预算与结算

- 原始预算保留在原始金额；
- 书面确认的增减写入已确认增减；
- 口述约数、未签报价和可能产生的费用写入待确认增减；
- 当前金额写明计算公式和来源；
- 全局预算变化同步到关键口径表；
- 每笔增改尽量关联报价单、变更单、发票或付款凭证；
- 最终结算前检查重复项、漏项、管理费和已付金额。

### 4. 分阶段验收

验收建议按当前施工阶段生成，避免给出已经过期的准备事项。

常见专项：

- 柜体：结构图、尺寸、门板、缝隙、五金、封边、收口、打胶、设备位；
- 墙地面与美缝：材料、颜色、施工范围、平缝/压缝、阴阳角、污染、开裂、养护和质保；
- 卫浴：坑距、给排水、试水、渗漏、防霉胶、玻璃和五金；
- 门窗：开合、密封、隔音、排水、玻璃和五金；
- 灯具和电气：回路、点位、色温、显色、防眩和安全；
- 家电设备位：净尺寸、门向、插座、给排水、散热、网络和搬运通道。

每个整改项至少记录问题、责任方、完成标准、期限和复验结果。

### 5. 设备入户

入户前检查：型号、尺寸、搬运通道、安装点位、水电网络和成品保护。

入户后检查：外观、数量、安装、通电/试水、噪声、渗漏、配件、序列信息和保修资料。

设备已经投入使用后，应从待入户清单移除，并同步资产台账；未入户设备继续保留条件和下一步。

### 6. 与资产台账联动

- 装修台账记录预算、付款、送货、安装、验收和结算；
- 资产台账记录真实成交金额、归属、启用、保修、成本和退役；
- 已购买未启用映射为资产`已购买待启用`；
- 实际投入使用后映射为`使用中`；
- 装修暂估金额不得覆盖更可靠的订单实付金额；
- 状态变化时检查两张表，但只更新有明确证据的字段。

### 7. 资料归档

推荐目录：

- `01_总览与进度`；
- `02_预算与报价`；
- `03_设计图纸与图片`；
- `04_合同与付款`；
- 可选的`05_验收与整改`。

上传后回读目录，核对文件名、数量和位置。重复文件先比较来源、时间和内容，不直接删除。

## 输出格式

日常摘要优先包含：

1. 当前阶段；
2. 已完成；
3. P0/P1下一步；
4. 金额变化与计算口径；
5. 待确认事项；
6. 已更新的飞书入口。

不在回复中堆砌内部 token、table ID、record ID 或底层命令。

## 完成检查

- 实时读取了飞书数据；
- 状态、金额和面积等口径没有混淆；
- 已确认、待确认和情景值分离；
- 建议符合当前施工阶段；
- 设备状态与资产台账无明显冲突；
- 所有写入已回读验证；
- 删除或对外动作已取得授权；
- 输出未泄露个人、合同或账号敏感信息。
